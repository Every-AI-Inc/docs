## Overview

The **Every CLI** (`@everyai/cli`) gives you and your coding agents command-line access to your Every workspace — people, companies, invoices, proposals, deals, pipeline, payments, and more. Install it once, sign in once, and the same `every` command works everywhere a shell runs: Claude Code, Codex, Cursor, a plain terminal, or a CI job.

Under the hood the CLI is a client of Every's [MCP server](/integrations/connect-ai-tools), so it discovers the current tool surface automatically. Keep the CLI current for new client-side behavior such as approval handling.

<Note>
  If you'd rather use Every *inside* one assistant, you can add the MCP server to it directly — see [Connect to Claude & ChatGPT](/integrations/connect-ai-tools). The CLI is the portable alternative: one install and one login cover every agent and machine context, including CI, where per-assistant MCP config isn't practical.
</Note>

## Install and sign in

Requires [Node.js](https://nodejs.org) 18 or newer.

<Steps>
  <Step title="Install globally">
    ```bash
    npm install -g @everyai/cli
    ```
    This installs two identical commands: `every` (primary) and `everyai` (alias).
  </Step>
  <Step title="Sign in">
    ```bash
    every login
    ```
    Opens your browser to authenticate with your Every account (OAuth 2.0 + PKCE). Tokens are stored in your operating system's keychain and refreshed automatically — you won't need to sign in again for a long time.
  </Step>
  <Step title="Confirm who you are">
    ```bash
    every whoami
    ```
    Shows the signed-in user, the **organization** your commands act on, the environment, and how many tools are available. Always worth checking before a write, so you know exactly which workspace it lands in.
  </Step>
</Steps>

<Note>
  **Headless / CI:** set the `EVERY_TOKEN` environment variable to a valid access token to skip the browser flow entirely. `every login` requires an interactive terminal and exits with code `3` without one, so it never hangs a script. `every signup` (below) does not need a terminal.
</Note>

## Sign up for Every from the CLI

New to Every? `every signup` creates your account, or signs you in if you already have one, in one browser step. A coding agent can run it for you: it needs no interactive terminal and never waits for Enter. Requires CLI 0.8.0 or newer.

<Steps>
  <Step title="Authorize in the browser">
    ```bash
    every signup
    ```
    The CLI prints an authorization URL, tries to open your browser, and waits up to 5 minutes (`--timeout <seconds>` to change it). Sign in or create your account on Every's own page. The CLI never sees your password or any code.
  </Step>
  <Step title="Confirm your business name">
    If the account is new, the CLI reports `needs_profile` with suggested values for your organization name, description and public links, inferred from your mailbox and the web. Suggestions are unverified: confirm or change them.
    ```bash
    every signup complete --org-name "Acme Studio" --description "Brand design for startups" --link https://acme.studio --yes
    ```
    Only `--org-name` is required. The account is ready as soon as this returns; Business DNA and other setup continue in the background.
  </Step>
  <Step title="Check status any time">
    ```bash
    every signup status
    ```
    Returns `ready` for an account that is good to go.
  </Step>
</Steps>

Until signup is finished, other tools return `error.code: "signup_incomplete"` and the CLI names the command that finishes it. If the browser step is denied or times out, the command exits `3`; run `every signup` again. `every login --create-account` still works as an alias for `every signup`.

<Tip>
  **For agents:** run `every signup --json`. Stdout is NDJSON: an `authorization_required` event with the `url`, a `waiting_for_authorization` event with `browser_opened`, then the usual envelope. Give the person the URL only if `browser_opened` is false. Ask once to confirm the organization name (and, optionally, description and links), then run `every signup complete ... --yes --json`. Never ask for passwords, codes or tokens.
</Tip>

## Output contract

Every command supports `--json`. In JSON mode, stdout is **exactly one JSON document** and nothing else, so it's safe to pipe and parse:

```jsonc
// success
{ "ok": true,  "data": { /* ... */ },                    "env": "production", "schema_version": 1 }
// failure
{ "ok": false, "error": { "message": "...", "code": "..." }, "env": "production", "schema_version": 1 }
```

Branch on the process **exit code** rather than scraping text:

| Code | Meaning | What to do |
|-|-|-|
| `0` | Success | Read `data` |
| `1` | Tool or generic error | Read `error.message` before retrying |
| `2` | Usage error | Fix the command or arguments |
| `3` | Auth required or expired | Run `every signup` (any context), or `every login` at a terminal |
| `4` | Permission / confirmation needed | Add the required local safety flag, or approve a pending sensitive action in Every and retry identically |
| `5` | Rate limited | Back off and retry |
| `6` | Not found | Re-list and verify the ID |
| `7` | Network / timeout | Check connectivity and retry |

The `env` field on every JSON response tells you whether the command targeted `production`, `staging`, or a `custom` server — a quick way to confirm blast radius.

## Safety model

The CLI classifies every tool and gates it locally, then Every applies its server-side approval policy:

- **Reads** run freely.
- **Writes** (create/update) require `--yes`.
- **Destructive or external-impact actions** — sending invoices, proposals and deal messages, deletes, voids, recording payments — require **both** `--yes` and `--allow-destructive`.
- **`--read-only`** (or the `EVERY_READ_ONLY=1` environment variable) blocks anything that isn't a read, for safe automation.

Each verb gets the gate that fits it:

| Command | Local flags | In Every |
|-|-|-|
| `list`, `view`, `deal stages`, `approvals` | None | Runs at once |
| `create`, `update`, `deal move`, `deal outreach edit`, `deal outreach cancel` | `--yes` | Confirmation phrase, handled by the CLI |
| `invoice send`, `proposal send`, `deal outreach send` | `--yes --allow-destructive` | Waits for your approval in Settings → Approvals |
| `every tool call deal_outreach` (any action) | `--yes --allow-destructive` | A send waits for approval. Edit and cancel take a confirmation phrase |

For ordinary writes, Every may return an exact action-and-target confirmation. In an interactive terminal, CLI 0.6.3 or newer can confirm the trusted phrase and retry once after your local consent.

Higher-impact actions also create a request in [**Every → Settings → Approvals**](https://app.every.ai/settings/approvals). The CLI never automatically retries a human-approved action: after approving, rerun the identical command with the same arguments and flags within 24 hours. An approval belongs to the connection that asked for it, and can be used once.

Archiving a deal from the CLI needs only the confirmation phrase, not an approval, because you can restore it. Archiving or deleting People and Companies, deleting deals, and every send still wait for approval.

In a non-interactive context, a missing flag fails fast with exit code `4` and names the exact flag needed — it never silently prompts and hangs.

```bash
# See how a specific tool is classified and what it requires
every policy explain send_invoice --json
```

<Warning>
  Only add `--yes` when the human explicitly asked for the change, and only add `--allow-destructive` when they explicitly asked for the send/delete/payment. These flags confirm local intent; they do not replace a server-required approval.
</Warning>

## Commands

<CodeGroup>
```bash Discovery
every docs                         # full command tree + conventions, offline
every tools list                   # all available tools with safety classification
every tools list --filter invoice  # filter by substring
every tools describe list_invoices # schema + policy + guidance for one tool
```

```bash Run any tool
# Inline arguments (repeatable); values are parsed as JSON when possible
every tool call list_invoices --arg payment_status=overdue --arg limit=100 --json

# Or pass a JSON object as a file, or on stdin with -
every tool call create_invoice --args invoice.json --yes --json
```

```bash Curated aliases
every invoice list --status overdue --json
every invoice create --client "Acme Consulting" --amount 100 --yes --json
every invoice send <invoice_id> --yes --allow-destructive --json
every deal stages --json           # your workspace's stages, in order
every deal list --stage "Discovery booked" --json
every deal move <deal_id> won --yes --json
every contact list --search "acme" --json
```

```bash People & Companies
every company list --search "acme" --json
every company view <company_id> --json
every company create --name "Acme Consulting" --website https://acme.example --yes --json
every person view <person_id> --json
every person create --name "Jane Doe" --email jane@example.com --company "Acme Consulting" --yes --json
```

```bash Deals
every deal list --attention needs_reply,step_due --json   # deals that need you
every deal list --stale-days 14 --mine --json             # your deals with no activity for 14 days
every deal list --since 2026-11-09T08:00:00Z --sort last_activity_at --json
every deal view <deal_id> --plan --draft --auto-sends --json
every deal create --person-id <person_id> --deal-name "Q1 brand refresh" --value 12000 --yes --json
every deal update <deal_id> --value 15000 --owner me --yes --json
every deal move <deal_id> "Proposal sent" --yes --json
```

```bash Deal messages & approvals
every deal outreach edit <deal_id> --body-file reply.txt --yes --json
every deal outreach send <deal_id> --yes --allow-destructive --json
every deal outreach cancel <deal_id> --send-id <send_id> --yes --json
every approvals --json             # requests from this connection that wait or are approved
every approvals --all --json       # every request of the last 24 hours
```

```bash Auth & identity
every signup                       # create an account, or sign in, in one browser step
every signup status                # is signup finished?
every login                        # browser sign-in (interactive terminal)
every whoami                       # user, org, environment, tool count
every auth status                  # local session state (no network)
every org                          # the organization commands act on
every logout
```
</CodeGroup>

`every invoice create` resolves the client by name — if the name is ambiguous it returns exit code `6` with the candidate list (each `client_id` and name) so a retry with `--client-id` is mechanical.

Short commands such as `every deal update` call one tool each. `every tool call <tool>` still works for every tool. Stages are per workspace, so `--stage` and `deal move` take a stage key or a label from `every deal stages`. Short commands for companies, people, deal views and updates, deal messages and approvals need CLI 0.10.0 or newer.

### Update a deal

`every deal update` changes only the fields you pass: `--name`, `--value`, `--owner` (`me`, a teammate's email or a user id), `--person-id` or `--company-id`, `--add-member` and `--remove-member`. It has no goal flag, because a goal change replaces the whole goal. To change what a deal sells, call the tool directly:

```bash
every tool call update_deal --args goal.json --yes --json
```

`update_deal` replaces the older `set_deal_name` and `set_deal_value_estimate` tools. They still work for now, but new scripts should use `update_deal`.

### Send a deal's next message

Every keeps one draft for the message a deal owes. Read it, edit it if needed, then ask to send it:

<Steps>
  <Step title="Read the draft">
    ```bash
    every deal view <deal_id> --draft --json
    ```
    The result shows the draft's channel (email, LinkedIn or Instagram), recipient, subject, text and draft version.
  </Step>
  <Step title="Edit it (optional)">
    ```bash
    every deal outreach edit <deal_id> --subject "Next steps" --body-file reply.txt --yes --json
    ```
    `--recipient` must be an email address of a Person on the deal. `--thread` takes one of the deal's Gmail threads, or `new` for a new email. A LinkedIn or Instagram draft has only a body.
  </Step>
  <Step title="Ask to send it">
    ```bash
    every deal outreach send <deal_id> --yes --allow-destructive --json
    ```
    The CLI reads the draft again, shows its channel, recipient, subject and text, and asks to send that exact version. Pass `--draft-version <v>` to send a version you already read. Every then holds the send for you: the command exits `4`, and `error.approvals_url` links to Settings → Approvals.
  </Step>
  <Step title="Approve, then run the same command again">
    Review the To, Cc, subject and text on the approval card and approve it. Then rerun the identical command within 24 hours to send.
  </Step>
</Steps>

If the draft changed after you approved, or a new reply reached the deal, Every refuses the send and nothing goes out. Read the draft again and ask for a new approval. If the send fails at your mail provider, the approval is used up. If the channel can't be sent from Every, for example because your LinkedIn or Instagram account isn't connected, the result gives you the text to send yourself.

To stop a scheduled or held send, use `every deal outreach cancel <deal_id> --send-id <send_id> --yes`. The send ids are in `every deal view <deal_id> --auto-sends`.

### Check approvals

`every approvals` lists the requests that wait for approval in Every: status, tool, deal and action, the connection that asked, and when each was created and expires. By default it shows the pending and approved requests of this connection. `--all` shows every request of the last 24 hours. It is read only: you approve in [**Settings → Approvals**](https://app.every.ai/settings/approvals), never from the CLI.

## For AI agents

If you're a coding agent driving this CLI, four rules make you reliable:

<Tip>
  1. **Always pass `--json`** and read the envelope (`ok`, `data`/`error.code`, `env`, `schema_version`).
  2. **Branch on exit codes**, not on stderr text — exit `3` means run `every signup` (or ask the user to run `every login` at a terminal).
  3. **Never guess an ID.** List or search first, then act with the exact ID returned in `[id: ...]`.
  4. **Only add `--yes` / `--allow-destructive` when the human explicitly asked** for that write or send.
</Tip>

Every ships a skill that encodes these rules plus Every's domain workflows. Install it so your agent follows them automatically — see [Agent skill (use-every)](/cli/agent-skill).
