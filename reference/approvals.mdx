## Overview

Every asks for an additional approval before a sensitive action can run. The approval method depends on where you made the request:

| Where you asked | How you approve | Approval window |
|-|-|-|
| Emailing `agent@every.ai` | Reply in the same email thread with the exact command Every provides | 24 hours |
| ChatGPT, Claude, Cursor, Every CLI, or another Admin MCP client | Review the action in the Every web app, then retry the identical request if needed | 24 hours |

Approvals are tied to the person, organization, action, and exact target. They are single-use and cannot authorize a changed request.

## Email-agent approvals

You can start naturally by emailing `agent@every.ai`:

```text
Delete invoice INV-123.
```

Every first resolves the invoice and emails back its organization, billed person or company, invoice number, amount, status, and ID. Nothing is deleted at that point.

### Approve or cancel

To approve, reply directly to the current confirmation email with only:

```text
DELETE INVOICE INV-123
```

To cancel, reply with only:

```text
CANCEL DELETE INVOICE INV-123
```

Copy the invoice number exactly as Every shows it. The command words are case-insensitive, but the invoice number is literal and case-sensitive.

<Note>
  Your newly written reply must contain only the command. Gmail's standard quoted reply history beneath it is ignored, but extra prose or an email signature in the newly written portion will not approve the action.
</Note>

### What Every checks

- The reply came from the same authenticated email account
- It is in the same Gmail thread and replies to the current confirmation email
- The approval is still within its 24-hour window and has not been used
- The invoice still matches the details you reviewed
- You still belong to the organization that owns the invoice

Every emails the final result. Repeating a used command cannot delete the invoice again. If the invoice changed, disappeared, became ineligible for deletion, or your organization access changed, Every refuses the deletion and explains why.

### Sending by email — approve with a one-time code

Outbound sends requested over email — **sending an email, an invoice, or a proposal** — use the same reply-approval pattern with a one-time code instead of a record number. Ask naturally ("Send the ACME invoice"), and Every replies with the full send details — recipient, document, amount — plus a command like:

```text
SEND 7f3ka92m
```

Reply directly to that confirmation email with only the command to approve, or with `CANCEL SEND 7f3ka92m` to cancel. Each code is high-entropy and **single-use**: it matches exactly one prepared send, so a reply can never approve a different pending action, and Every's delivery machinery guarantees a send is **never dispatched twice** — even if something crashes and retries mid-send.

The same checks as deletion apply: same authenticated sender, same thread, within the 24-hour window, unused, and your organization access unchanged.

<Note>
  Email approval currently supports **outbound sends** (emails, invoices, proposals) and **invoice deletion**. Scheduled tasks cannot use this flow, and other destructive actions remain unavailable during unattended email-agent runs.
</Note>

## MCP-client approvals

Every applies the same server-side safety gate whether you connect through ChatGPT, Claude, Cursor, the Every CLI, or another **Admin MCP** client.

- Read-only requests run immediately.
- Ordinary workspace changes may require the client to repeat an exact action-and-target confirmation supplied by Every.
- Higher-impact actions require you to review the complete action details and choose **Approve** or **Cancel** in the Every web app. These include sends, deletes, archiving or deleting People and Companies, and prospect rejections.
- **Archiving a deal** from the Every CLI or a direct MCP connection (for example Claude Code, Codex or Cursor) needs only the typed confirmation, with no approval in the app, because you can restore an archived deal at any time. From the ChatGPT app or a Claude.ai connector, it still needs your approval.

### Approve and continue

1. Ask your connected AI client to perform the action.
2. Open [**Every → Chat → Approvals**](https://app.every.ai/chat/approvals) and inspect the exact action details.
3. Choose **Approve** or **Cancel**.
4. If the AI client returned a pending message, ask it to retry the **same action with the same arguments**.

Every may keep the original tool call open for up to 30 seconds. That wait is separate from the approval window: the request stays open for **24 hours** from creation, and an approval can be consumed only once. Changing any argument creates a different approval request. Denied, expired, or already-used approvals cannot execute the action.

Each approval belongs to the connection that asked for it. Another AI client or CLI session can't use it, even when it is signed in as you.

### Deal messages

When an agent asks to send a deal's next message, the approval card shows the exact **To** and **Cc** addresses, the subject, and the message text, with a note for any recipient address or profile that was added or changed in the last 7 days. Check every address before you approve. Only the deal's owner can send its message.

An approved deal send is tied to the exact draft you reviewed:

- If the draft, its recipients or its email thread changed after you approved, the send is refused and nothing goes out. An edit after approval needs a new approval.
- If a new reply reached the deal after the agent asked, the send is refused, so an answer never goes to a conversation that has moved on.
- If the send fails at your mail provider, the approval is used up. The agent must ask again.

### Approve a whole agent run at once

A scheduled agent can ask for several approvals in one run. Requests from the same connection that arrive close together are grouped. Review the items, then choose **Allow all** or **Cancel all** for the group, or decide each one separately.

The agent doesn't wait inside its run. It picks up your decisions on its next run and repeats each approved request exactly. See [Automate your CRM with an agent](/integrations/automate-with-an-agent).

<Warning>
  MCP approvals are currently completed in the Every **web app**. Mobile approval for these external-client requests is not yet available.
</Warning>

### Notes by client

| Client | What to expect |
|-|-|
| **ChatGPT, Claude, and Cursor** | The client may keep waiting or return a pending message. After approving in Every, ask it to retry the exact action if it did not continue automatically. |
| **Every CLI 0.6.3 or newer** | Rerun the identical command, including the same arguments and safety flags. The CLI never automatically retries a human-approved action. With CLI 0.10.0 or newer, `every approvals` lists what waits and what you approved. |
| **Other MCP clients** | Presentation and timeout behavior vary. Preserve the exact arguments when retrying after approval. |

## Troubleshooting

<AccordionGroup>
  <Accordion title="I approved the action, but nothing happened">
    Your AI client may have stopped waiting before you approved, or a scheduled agent picks it up on its next run. Ask it to retry the exact same action with the same arguments within 24 hours. For the Every CLI, rerun the identical command.
  </Accordion>
  <Accordion title="Every created another approval request">
    One or more arguments changed, the original approval expired, or the original approval was already consumed. Review the new request as a separate action.
  </Accordion>
  <Accordion title="My email reply did not approve the deletion">
    Reply directly to the current confirmation email from the same account. Put only the exact command in the newly written portion, copy the invoice number exactly, and remove signatures or extra commentary.
  </Accordion>
</AccordionGroup>
